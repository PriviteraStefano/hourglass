## Typography

Matching existing project patterns (verified from existing components):

| Role | Size | Weight | Line Height | Element |
|------|------|--------|-------------|---------|
| Body | 16px | 400 (regular) | 1.5 | Paragraph text, form labels |
| Label | 14px | 500 (medium) | 1.4 | Field labels, table headers, secondary text |
| Heading | 18px | 600 (semibold) | 1.2 | Day detail heading ("Monday, June 13, 2026"), section titles |

**Usage rules:**
- **Data rows** (entry-row, expense-row, approval-history items): Body 16px/400 for primary content, Label 14px/500 for field headings, Small 12px/400 for timestamps and secondary metadata.

- **Calendar navigation:** Label 14px/500 for month/year header.

**Source:** `entry-detail.tsx` uses `text-lg font-semibold` for heading, `text-sm text-muted-foreground` for secondary. `status-badge.tsx` uses `text-xs font-medium`. `Button` uses `text-xs/relaxed`.

### Interaction Details

1. **MiniCalendar navigation:**
   - Click a date → navigates to `?date=<date>&month=<month>` for that domain
   - Month arrows → changes `month` search param
   - Day cell colored by highest-priority status on that day: approved > rejected > submitted > draft
   - Legend below calendar shows all 6 status colors

2. **Day detail panel:**
   - Header: "Monday, June 13, 2026" + aggregate StatusBadge of the entry
   - Flat list of entries for that date (one row per project)
   - Each row: Project select, hours input, description, StatusBadge, action buttons
   - Sorting: by project name alphabetical
   - Empty state when no entries for that date: CTA button only

3. **Create/Edit workflow:**
   - **Entry already exists for date:** show the entry in editable form
   - **No entry for date:** show CTA button "Create Entry" — clicking creates a draft entry with one empty row
   - **Flat model (D-01):** single entry per date, each row maps to a project
   - **Edit:** Save Draft updates the entry inline
   - **Delete:** AlertDialog confirmation → DELETE request → redirect to empty state

4. **Submit workflow (D-15):**
   - Click "Submit Entry" → POST /time-entries/{id}/submit
   - Status transitions: draft/rejected → submitted (current_approver_role=manager)
   - Toast on success; cache invalidation for `['time-entries']` prefix

5. **Approve/Reject workflow (D-08, D-09, D-10, D-11):**
   - Approve button: visible only if user role matches current_approver_role
   - Reject button: visible alongside Approve
   - Reject opens inline textarea for reason (required, minimum 10 chars)
   - Both actions create synchronous approval history record
   - Self-approval prevention (D-11): if creator == WG manager, skip pending_manager

6. **Expense-specific interactions:**
   - Category selector dropdown with 9 options (D-04)
   - km_distance field visible only when category="mileage" (D-07)
   - Receipt upload button: shows file picker (PDF/JPEG/PNG, <10MB)
   - After upload: receipt_url shown as download link with file icon
   - Amount field: currency input (no symbol prefix, decimal allowed)

7. **Cache invalidation (Pitfall 4):**
   - After create/update/delete: invalidate `['time-entries']` prefix
   - After approve/reject: invalidate both `['time-entries']` AND `['time-entries', 'month', ...]` prefix for month view
   - Same pattern for expenses: `['expenses']` AND `['expenses', 'month', ...]`

### Shared Components

**approval-buttons.tsx** (D-18):
- Props: `entryId`, `entryStatus`, `currentApproverRole`, `userRole`, `onApprove`, `onReject`
- Renders Approve (primary) + Reject (destructive with textarea) buttons

- Already supports all 6 statuses with correct colors
- Reused without modification for both time entries and expenses

## Query Key Convention

| Domain | Key Pattern | Example |
|--------|------------|---------|
| Time entries (month) | `['time-entries', 'month', month, year]` | `['time-entries', 'month', 6, 2026]` |
| Time entries (date) | `['time-entries', 'date', dateStr]` | `['time-entries', 'date', '2026-06-13']` |
| Time entries (pending) | `['time-entries', 'pending']` | `['time-entries', 'pending']` |
| Expenses (month) | `['expenses', 'month', month, year]` | `['expenses', 'month', 6, 2026]` |
| Expenses (date) | `['expenses', 'date', dateStr]` | `['expenses', 'date', '2026-06-13']` |
| Expenses (pending) | `['expenses', 'pending']` | `['expenses', 'pending']` |
| Approval history | `['approvals', domain, entryId]` | `['approvals', 'time-entry', id]` |

**Cache invalidation:**
- Mutations invalidate by prefix: `client.invalidateQueries({ queryKey: ['time-entries'] })` or `['expenses']`
- Approve/reject additionally invalidate month-level: `['time-entries', 'month']` and `['time-entries', 'pending']`

**Source:** D-14, D-15 (client-side month computation, no monthly-summary endpoint). Specifics section query key convention in CONTEXT.md.
