<task id="2">
<type>execute</type>

<action>
Refresh-token rotation integration + unit tests (P0-5 regression).

Unit (service layer, mocked repo):
- `Rotate` happy path returns new pair, marks old row rotated
- Reuse of rotated token → `ErrTokenReuse` + family revoke called
- Revoked-family token → rejected

Integration (testcontainers):
- Login → capture refresh cookie → refresh → second refresh token differs from first
- Replay the first token → 401
- After replay, the latest valid token of that family also fails (family revoked)
- Parallel reuse race: two concurrent refreshes with the same token → exactly one succeeds
</action>

- Plan 01 task 2 implementation (`token_service.go` Rotate + tokens repo)
- `internal/adapters/primary/http/auth_test.go` (existing refresh tests to extend)
- testify suite conventions from Phase 0 rewrites
</read_first>

- The concurrency case is deterministic in CI (no flaky timing — synchronize via transaction isolation or sequential replay)
- Total auth package coverage does not decrease
</acceptance_criteria>
</task>
