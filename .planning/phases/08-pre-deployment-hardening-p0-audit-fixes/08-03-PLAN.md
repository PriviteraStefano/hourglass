<task id="1">
<type>execute</type>

<action>
Refresh-token reuse-detection tests (P0-5 regression).

Unit (service layer, mocked repo):
- Atomic rotate happy path: marks old row rotated, inserts successor with same `family_id`, returns new pair
- Reuse of a rotated token → `ErrTokenReuse` + `RevokeFamily` called with the right family
- Reuse of a revoked-family token → `ErrTokenReuse`
- Mid-rotate failure → no partial state (old token NOT revoked without successor)

Integration (testcontainers, real PostgreSQL — `internal/adapters/secondary/postgres/refresh_token_repo_test.go` + auth service tests):
- Login → refresh → refresh: each token differs; cookie updated each time
- Replay the first token → 401
- After replay: latest valid token of that family ALSO fails (family revoked)
- Concurrent race: two parallel refreshes with the same token → exactly one succeeds; the loser gets 401 without corrupting the family (no spurious family revoke from a legitimate concurrent loser — distinguish race-loser from attacker-replay; document the chosen semantics in the test)
</action>
