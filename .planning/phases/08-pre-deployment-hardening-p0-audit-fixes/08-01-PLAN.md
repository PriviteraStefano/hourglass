# Plan 08-01 — Backend Security Hardening

> **Rescoped 2026-07-31 after code verification.** P0-1 (status CHECK) was already fixed by `migrations/004_time_entries_status_check.up.sql`; P0-6 (reset-code exposure) was already fixed and regression-tested per D-16. Both are closed — see the audit note's Corrections section. What remains on the backend: the **reuse-detection layer** on top of the *existing* refresh rotation (P0-5-lite), plus S3 input length caps.

**Verified current state (do not re-litigate):**
- `Refresh` (`internal/core/services/auth/auth.go:349–404`) already rotates: `RevokeByHash` old + `Add` new.
- `RefreshToken` persistence (`internal/core/ports/refresh_token_repo.go`) has NO rotation state — no `family_id`, `rotated_at`, `revoked_at`.
- Rotate runs as 3 separate statements (FindByHash → RevokeByHash → Add) with no transaction.

<task id="1">
<type>execute</type>

<action>
Add refresh-token reuse detection with family revocation (P0-5, rescoped). Build on the existing rotation — do NOT re-implement it.

- Migration `010_refresh_token_reuse_detection`: add `family_id UUID` (NULL-able for existing rows, backfill each existing row with its own `gen_random_uuid()` family), `rotated_at TIMESTAMPTZ NULL`, `revoked_at TIMESTAMPTZ NULL`; index on `family_id`. Existing `RevokeByHash` currently DELETEs or flags rows — check the repo implementation first; move to a `revoked_at` tombstone model so replayed hashes remain detectable.
- Extend `ports.RefreshToken` with `FamilyID`, `RotatedAt *time.Time`, `RevokedAt *time.Time`; extend the repository interface with `RotateWithinTx`-style support and `RevokeFamily(ctx, familyID)` — keep `RevokeAllByUser` (used by password reset Verify at auth.go:97).
- Rewrite `Service.Refresh` rotation into ONE transaction (pgx `BeginTx` via the pool or a repo-level atomic method): find by hash → if row has `rotated_at`/`revoked_at` set → `RevokeFamily(family_id)` + return `ErrTokenReuse` sentinel (new, in `internal/core/services/auth/errors.go`) → else mark `rotated_at=now()`, insert successor with same `family_id`, return new pair.
- New token families: login/register/bootstrap issue paths set a fresh `family_id` per session.
- Handler (`internal/adapters/primary/http/auth.go` Refresh): map `ErrTokenReuse` → 401 + clear both cookies (`auth_token`, `refresh_token`); other invalid-token errors keep current behavior.
</action>
