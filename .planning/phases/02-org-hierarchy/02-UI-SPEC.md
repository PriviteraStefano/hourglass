## Spacing Scale

Tailwind CSS v4 default spacing scale (multiples of 4). All existing code uses standard Tailwind spacing tokens.

| Token | Value | Usage in This Phase |
|-------|-------|---------------------|
| xs | 4px | Inline icon gaps (`gap-1`, `mr-1`), compact element padding (`px-1`, `py-0`) |
| sm | 8px | Compact spacing between list items (`gap-2`, `space-y-0.5`), button padding (`px-2`, `py-1`) |
| md | 16px | Default element spacing (`gap-4`, `space-y-4`, `p-4`), section padding |
| lg | 24px | Section separation (`space-y-6`, `mt-6`), sheet content padding |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Sheet width (`w-[400px]`), large dividers |
| 3xl | 64px | Page-level spacing (root padding) |

**Exceptions:**
- **Touch targets**: Compact action buttons use `h-6` (24px) for inline icon buttons (X close, Make Primary), `h-7` (28px) for labeled buttons (Add Member). These are below the 44px WCAG recommended minimum but follow the established project pattern for dense tree/side panel UIs where space is constrained.
- **Sheet width**: Fixed at `w-[400px] sm:max-w-[400px]` per existing `UnitDetailPanel` — matches the project's established sheet sizing.

### Accent Reserved For

Accent (primary-400 green) is reserved for these specific elements in this phase:
1. **ReactFlow connection lines** — Drawn when user drags edge between nodes (theme default via `@xyflow/react`)
2. **Primary buttons** — The "Move" confirm button in ReparentConfirmDialog (`AlertDialogAction` styled by shadcn)
3. **Focus/selection rings** — `ring-primary-400` on form inputs, command items, menu items
4. **"Primary" badges** — `Badge variant="outline"` border (inherits accent via `--ring` variable)
5. **Edit button** — `Button variant="outline"` inherits accent from ring/border colors (not a dedicated accent button)

**Explicitly NOT accent:** Delete button (destructive red), Remove member X (muted foreground), breadcrumb separators (muted), sheet close button (muted)

## Interaction Contract

### 1. Member Row — "Make Primary" Button (D-01)

```
State: User hovers over a non-primary member row in the side panel
  → "Make Primary" ghost button appears (opacity-0 → opacity-100 transition)
  → User clicks "Make Primary"
  → Mutation fires PUT /units/{id}/members/{membershipId} { is_primary: true }
  → On success:
    → Toast: success("Set [name] as primary member")
    → Invalidate ['units', 'members', unitId]
    → Invalidate ['units', 'tree']
    → Re-render: "Primary" badge moves from old member to this member
    → Button returns to hidden state (member is now primary)
  → On error:
    → Toast: error("Failed to update member")

Edge cases:
  - Member is already primary: Button not shown (Badge variant="outline" "Primary" shown instead)
  - Last member being set as primary: allowed (no minimum primary constraint)
  - Network error: Toast shows error, state unchanged
```

### 2. Subtree Members Section (D-15, D-16)

```
State: Side panel open showing a unit with at least one child unit
  → "Direct Members" section rendered as before (existing list)
  → "Sub-unit Members" section rendered below
  → Each child unit shown as a collapsible group:
    → Header: "[▶/▼] [Sub-unit Name] (N members)"
    → Default: collapsed (closed)
  → User clicks group header:
    → Chevron rotates (ChevronRight → ChevronDown via lucide-react)
    → Members fetched via unitMembersQueryOpts(childUnitId)
    → Member rows rendered with same MemberRow component
    → Child units' children rendered recursively with increased left indent (+12px per level)
  → User clicks group header again:
    → Chevron collapses back
    → Member rows hidden (query stays cached)

Implementation notes:
  - Each SubtreeGroup manages its own expanded state via Set<string> in SubtreeMembersSection
  - MemberRow in subtree groups does NOT show remove button or "Make Primary" button (read-only context)
  - Recursive nesting: child units within expanded groups show as further nested collapsible groups
  - Query enabled only when group is expanded: `enabled: expanded`
  - Batch endpoint (D-13) can replace per-unit fetches if available
```

### 3. Reparent Confirm Dialog — Mutation Switch (D-08)

```
Change from:
  useMutation(updateUnitMutationOpts)
  // Sends full unit body { name, code, description, parent_unit_id }

Change to:

Additionally:
  - Remove `pendingEdgeConnect` references from dialog (line 19, 34, and store reads)

Flow unchanged:
  onConnect → reparentUnit(source, target) → dialog reads draggingUnit/reparentTarget → confirm → reparentUnitMutationOpts
```

## Accessibility Notes

- **Touch targets**: Compact controls (Make Primary at `h-6`, Remove Member X at `h-6 w-6`) are below the 44px WCAG 2.1 Target Size recommendation. This is an existing project-wide pattern in dense tree/side panel UIs, acceptable for v0.1. Targets remain operable via single click.
- **Color contrast**: All color pairings (foreground/background, muted-foreground/background) are inherited from the shadcn base-mira olive preset which meets WCAG AA contrast ratios in both light and dark modes.
- **Focus indicators**: All interactive elements (buttons, popover triggers, command items) inherit focus ring styling from shadcn/ui via `ring-primary-400`.
- **Keyboard navigation**: Sheet, Dialog, Popover, and Command components from shadcn/ui provide built-in keyboard handling (Escape to close, arrow keys in Command list, Tab trap in dialogs).
- **Reduced motion**: The `opacity-0 group-hover:opacity-100 transition-opacity` pattern respects `prefers-reduced-motion` via Tailwind/shadcn defaults.
- **Screen readers**: All interactive elements have accessible labels: buttons use text content, icon buttons use `aria-label` (X close button via `Button` wrapper with text, PopoverTrigger with `render` prop).
