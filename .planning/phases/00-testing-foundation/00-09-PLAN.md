    Read BUGS.md and triage all bugs with severity "critical" and "high". For each bug:

    1. Understand the root cause from the bug description and location
    2. Fix the source code (modify the appropriate file)
    3. Run the relevant test that discovered the bug to confirm it now passes
    4. Update BUGS.md: change status from "open" to "fixed", add a "Fix" column note
    5. Commit with message referencing the bug ID: e.g., `fix: resolve BUG-001 - ...`

    For each bug, the fix approach depends on the type:
    - **500 errors / panics** during handler operations → fix the handler to return proper error responses
    - **Auth bypass** (endpoint works without auth when it shouldn't) → add/verify middleware.Auth wrapper in cmd/server/main.go
    - **Validation gaps** (endpoint accepts invalid data) → add validation in handler or service
    - **CORS issues** → fix CORS middleware configuration
    - **State transition errors** (wrong status allowed) → fix service submit/approve/reject logic
    - **Seed data / test data issues** → fix the test data source (not production code)
    - **Frontend integration issues** (api.ts not sending correct data) → fix the API client or hook

    Run `go test ./... -count=1` after each batch of fixes to confirm no regressions.
    Run `cd web && bun run test` after frontend fixes.

    After all critical/high bugs are fixed, update BUGS.md status column.
