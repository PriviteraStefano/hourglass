<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → auth handler | Login, register, refresh, password reset requests from untrusted clients |
| auth handler → auth service | Internal Go function call (within same process) |
| auth service → refresh token repo | Token persistence (revocation, addition of new tokens) |
| auth handler → cookies | Cookie setting on HTTP response for token delivery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-01-01 | Spoofing | POST /auth/refresh | mitigate | Refresh token rotation: old token revoked (RevokeByHash), new token issued. Stolen refresh token can only be used once. |
| T-00-01-02 | Information Disclosure | POST /auth/password-reset/request | mitigate | Reset code removed from response body. Delivered out-of-band only (email/SMS integration out of scope for this phase). |
| T-00-01-03 | DoS | Auth endpoints (login, password-reset) | mitigate | Separate rate limiters: login at 5/min anonymous, password-reset at 3/min anonymous. Prevents brute force and enumeration attacks. |
| T-00-01-04 | Elevation of Privilege | password reset code | mitigate | Entropy increased from 10^3 (1000 combinations, 3-digit) to 62^8 (~218 trillion). Combined with rate limiting (3/min), brute force is infeasible. |
| T-00-01-05 | Information Disclosure | Cookie names | mitigate | Cookie names unified to "auth_token" — consistent naming eliminates confusion between dead-code helpers and actual cookie setting. HttpOnly + SameSite=Strict on all cookies. |
| T-00-01-06 | Spoofing | nil pointer bugs | mitigate | Bug 1 (GetMemberships nil org) and Bug 4 (orgID nil) prevent server panics that could lead to information disclosure. Bug 3 (UUID parse) returns proper 400 instead of 500. |
</threat_model>
