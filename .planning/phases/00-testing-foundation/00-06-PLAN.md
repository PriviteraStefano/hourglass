    **Step A: Build and start the backend**

    Since our test infrastructure runs PostgreSQL via testcontainers, we need the backend to use a real PostgreSQL instance. The production code path uses `db.NewPool()` which reads `DATABASE_URL`.

    For E2E tests, we have two options:
    1. Use the existing Docker Compose PostgreSQL (runs on localhost:5432)
    2. Start a separate testcontainer-based PostgreSQL and run the server against it

    **Per D-09**: "ALL tests use testcontainers: service tests, handler tests, repository tests, smoke test (cmd/server/main_test.go), and Playwright E2E."

    **D-09 clarification — E2E exception**: The Playwright E2E test suite runs as a Node.js browser automation process against a real HTTP server. Unlike Go tests, Playwright cannot import `testcontainers-go` directly. Two approaches exist:
    - Option A (recommended): Start the backend with `DATABASE_URL` pointed at Docker Compose PostgreSQL. The backend's own startup uses `db.NewPool()` which reads `DATABASE_URL` — this is the production code path, not a test artifact. The testcontainers library tests the backend components (service/handler/repository tests); the E2E layer verifies the browser-to-backend integration. These are complementary, not overlapping.
    - Option B: Create a custom test binary or wrapper that starts the server against a testcontainers-managed PostgreSQL instance. This adds complexity (custom test entrypoint, port coordination) without meaningful coverage improvement — the backend code path is identical either way.

    **Recommendation (Option A)**: Use Docker Compose PostgreSQL for E2E tests. D-09's intent is full backend test coverage via testcontainers, which Plans 02-05 deliver. E2E tests verify the compiled binary against a running server — the DB connection mechanism is an infrastructure detail, not a coverage gap.
    ```bash
    # Start PostgreSQL via Docker Compose (if not already running)
    docker compose up -d postgres 2>/dev/null || true

    # Build and start the backend
    go build -o bin/hourglass ./cmd/server
    DATABASE_URL="postgres://hourglass:hourglass@localhost:5432/hourglass?sslmode=disable" \
      JWT_SECRET="test-e2e-secret" \
      ALLOWED_ORIGINS="http://localhost:3000" \
      ./bin/hourglass &
    SERVER_PID=$!
    sleep 2

    # Verify health endpoint
    curl -s http://localhost:8080/health | grep -q '"status":"ok"'

    # Run Playwright E2E tests
    cd web && bun install --frozen-lockfile 2>/dev/null
    cd web && bunx playwright test

    # Cleanup
    kill $SERVER_PID 2>/dev/null
    wait $SERVER_PID 2>/dev/null
    ```
