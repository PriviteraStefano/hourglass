<objective>
Contract `sold_hours` read/write (FND-03): add `contract_type`/`sold_hours`/`sold_period` to the contract domain, validate their semantics in the service, persist through the existing repository, and expose through the existing contract endpoints.

Purpose: V5 mines sold vs Σ actual hours (D-N). The semantics depend on contract type (D-07): `project` → sold_hours = lifetime total; `support` → sold_hours = hours per period, which requires `sold_period` (D-08/D-09). Legacy contracts keep `contract_type NULL` and are treated as project (D-16).
Output: domain fields, service validation, repo persistence, handler pass-through, unit + integration tests.
</objective>
