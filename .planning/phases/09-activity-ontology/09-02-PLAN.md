# Plan 09-02 — Staffing Schema

The additive schema from ADR-P-008 — one new table, three new columns, one enum extension. Zero FK coupling to the ontology rewrite (P-008 consequence §103: "rides the big-bang migration batch without expanding its blast radius"). Runs in the same wave as Plan 01 because they touch different tables.

**Schema only.** No surfaces, no queries, no export views — those are Phase 10 / v0.2.

<task id="1">
<type>execute</type>

<action>
Write `011_staffing_schema.up.sql` per the ADR-P-008 schema sketch.

- Create `availability_windows` table:
  - `id UUID PK DEFAULT gen_random_uuid()`
  - `org_id UUID NOT NULL REFERENCES organizations(id)`
  - `user_id UUID NOT NULL REFERENCES users(id)`
  - `kind VARCHAR(20) NOT NULL DEFAULT 'unavailable' CHECK (kind IN ('holiday','permit','medical','unavailable'))` — D-1
  - `starts_on DATE NOT NULL`
  - `ends_on DATE NOT NULL CHECK (ends_on >= starts_on)`
  - `hours DECIMAL(4,2)` — nullable; partial-day permits (D-1)
  - `certificate_ref VARCHAR(100)` — nullable; medical only, INPS protocol number, never the document (D-1a)
  - `note TEXT`
  - `status VARCHAR(20) NOT NULL DEFAULT 'declared' CHECK (status IN ('declared','confirmed'))` — D-1a: holiday→confirmed when both lines confirm
  - `created_by UUID NOT NULL REFERENCES users(id)`
  - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- Alter `organization_memberships`: add `valid_from DATE`, `valid_until DATE` (NULL = open-ended), `work_permit_expires_at DATE` (NULL = N/A) — D-2
- Extend `organization_memberships.role` CHECK constraint to include `'hr'` — D-4. Requires dropping and recreating the existing CHECK (PostgreSQL cannot alter CHECK constraints in place).
- Index on `availability_windows (org_id, user_id, starts_on, ends_on)` for the per-person date-range lookups the surfaces will need.
</action>
