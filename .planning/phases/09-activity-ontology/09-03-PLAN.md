# Plan 09-03 — Domain + Repository Collapse

Rewrites the domain model, port interfaces, and PostgreSQL adapters for the new ontology. `Project` and `Subproject` collapse into `Activity` (BE-014 R-6). All entry FKs re-point to `activity_id`. The commercial-chain and routing queries are rewritten as recursive CTEs against the activity tree.

Depends on Plan 01 (the schema must exist before queries can target it). Runs in parallel with Plan 02 (staffing schema — different tables, no overlap).

<task id="1">
<type>execute</type>

<action>
Create the `Activity` domain type and collapse the ports.

- `internal/core/domain/activity.go`: `Activity` struct with all ADR-P-007 D-2/D-3/D-7 fields (ID, OrgID, ParentID *uuid, Name, Description, Kind, ContractID *uuid, GovernanceModel, CreatedByOrgID, IsShared, Billable *bool, BudgetAmount *decimal, IsActive, CreatedAt, UpdatedAt). `ActivityKind` as a string type (not enum — free catalog per D-2). Request/response DTOs: `CreateActivityRequest`, `UpdateActivityRequest`, `ActivityFilter`.
- Delete `internal/core/domain/project.go` and `subproject.go` — any types still referenced elsewhere get moved into `activity.go` or the referencing file.
- Update `internal/core/domain/time_entry.go`: replace `ProjectID`, `SubprojectID`, `WGID` fields with `ActivityID uuid.UUID`. Keep `UnitID` (visibility pin per R-4).
- Update `internal/core/domain/expense.go`: replace `ProjectID`, `CustomerID` with `ActivityID uuid.UUID`. Keep `UnitID`.
- `internal/core/ports/activity_repository.go`: single interface replacing `project_repository.go` + `subproject_repository.go` — CRUD, ListByOrg, ListChildren(parentID), GetAncestry(id) (upward walk for commercial chain), ListByContract(contractID), adoption methods. Delete the two old port files.
- Update `internal/core/ports/time_entry_repository.go` and `expense_repository.go`: method signatures that took `projectID`/`subprojectID`/`wgID` now take `activityID`.
</action>

<task id="2">
<type>execute</type>

<action>
Rewrite the PostgreSQL activity repository.

- `internal/adapters/secondary/postgres/activity_repository.go`: implements the full port interface against the new `activities` + `activity_kinds` + `activity_adoptions` tables.
- `GetAncestry(id)`: recursive CTE walking `parent_id` upward — returns the chain from leaf to root. Used for commercial-chain resolution (D-3) and billability inheritance (D-7). Model on the existing units-subtree CTE pattern in `unit_repository.go`.
- `ResolveCommercialContext(activityID)`: walks ancestry to the nearest ancestor with `contract_id IS NOT NULL`, returns `(contract_id, customer_id)` or nil. This is the derived-never-stored query per D-3.
- `ResolveBillability(activityID)`: walks ancestry — nearest non-NULL `billable` wins; if the walk hits a contract-linked ancestor, defer to the contract's billability default.
- Delete `postgres/project_repository.go` and `postgres/subproject_repository.go`.
- Rewrite `postgres/working_group_repository.go`: `subproject_id` → `activity_id` in all queries; remove `enforce_unit_tuple` from column lists and INSERT statements.
- Rewrite `postgres/financial_cutoff_period_repository.go`: `project_id` → `activity_id`; `IsPeriodLocked` key becomes org + activity + date range (R-5).
</action>

<read_first>
- `internal/adapters/secondary/postgres/project_repository.go` + `subproject_repository.go` (current query patterns)
- `internal/adapters/secondary/postgres/unit_repository.go` (recursive CTE pattern to reuse)
- `internal/adapters/secondary/postgres/working_group_repository.go` + `financial_cutoff_period_repository.go` (current queries)
- `migrations/010_activity_ontology.up.sql` (the schema being queried — from Plan 01)
- `hourglass-vault/decisions/backend/ADR-BE-003 — Data Access pgxpool No ORM.md` (query conventions)
</read_first>

<acceptance_criteria>
- `activity_repository.go` implements the full port; old project/subproject repos are deleted
- `GetAncestry` returns the correct chain for a 3-level activity tree (test: engagement → phase → task)
- `ResolveCommercialContext` returns the contract+customer for a nested activity whose grandparent has `contract_id`; returns nil for a purely internal tree
- `ResolveBillability` returns the nearest non-NULL `billable` walking upward; falls through to contract default
- `working_group_repository.go` uses `activity_id` — no `subproject_id` or `enforce_unit_tuple` references remain

</task>

<task id="3">
<type>execute</type>

<action>
Rewrite the entry repositories' FK references.

- `postgres/time_entry_repository.go`: all queries replace `project_id`, `subproject_id`, `wg_id` with `activity_id`. INSERT accepts `activity_id` + `unit_id`. SELECT joins resolve activity name (and optionally kind) for list responses. `ListPending` for manager stage joins through `activities` → `working_groups` (activity_id) → `wg_members` (manager/delegate) — the R-1 chain. Visibility gating (R-4) unchanged: `unit_id` subtree CTE.
- `postgres/expense_repository.go`: same treatment — `project_id`, `customer_id` → `activity_id`. `ListPending` rewritten from the old project-manager join to the activity → WG join (matching time entries, per ADR-P-001 Q1 + BE-014 R-1/R-2).
- Both repos: update scan destinations, column lists, JOIN clauses, and WHERE filters throughout.
</action>
