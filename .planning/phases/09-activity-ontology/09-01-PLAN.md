# Plan 09-01 — Ontology Migration

The big-bang schema rewrite per ADR-P-007 D-6 and ADR-BE-014 R-5. One migration file replaces `projects` + `subprojects` with the recursive `activities` table, rewrites all FKs, drops dead columns, and migrates the MVP seed data. This is the foundation every other plan in this phase builds on.

<task id="1">
<type>execute</type>

<action>
Write `010_activity_ontology.up.sql` — the schema rewrite.

- Create `activity_kinds` table per ADR-P-007 D-2: `(org_id, name)` composite PK, `is_seed` boolean. Seed with `engagement`, `phase`, `task`, `internal` for the MVP seed org.
- Create `activities` table per ADR-P-007 D-2/D-3/D-7: `id`, `org_id`, `parent_id` (nullable, self-ref, ON DELETE RESTRICT), `name`, `description`, `kind` (FK to `activity_kinds`), `contract_id` (nullable, FK to contracts, ON DELETE RESTRICT), `governance_model` (CHECK, default `creator_controlled`), `created_by_org_id`, `is_shared`, `billable` (nullable boolean — NULL = inherit), `budget_amount`, `is_active`, `created_at`, `updated_at`.
- Create `activity_adoptions` mirroring `project_adoptions` shape (activity_id, adopting_org_id, adopted_at).
- Rename `project_managers` → `activity_managers` with `activity_id` column (migrate rows).
- Rewrite `working_groups`: `subproject_id` → `activity_id` (migrate rows), **drop `enforce_unit_tuple`** (ADR-P-001 Q3).
- Rewrite `time_entries`: drop `project_id`, `subproject_id`, `wg_id`; add `activity_id NOT NULL` (migrate from `subproject_id` → new activity id). Keep `unit_id NOT NULL`.
- Rewrite `expenses`: drop `project_id`, `customer_id`; add `activity_id NOT NULL` (migrate from `project_id` → new activity id). Keep `unit_id NOT NULL`.
- Rewrite `financial_cutoff_periods`: `project_id` → `activity_id`.
- Drop `projects`, `subprojects`, `project_adoptions` tables.
- Data migration (MVP seed): `projects` → `activities` with `kind = 'engagement'`, `parent_id = NULL`, `contract_id` preserved. `subprojects` → `activities` with `kind = 'task'` (review seed to confirm), `parent_id` = parent's new id, `contract_id = NULL` (inherits via D-3 upward walk). All entry FKs re-pointed in the same transaction.
</action>

<task id="2">
<type>execute</type>

<action>
Write `010_activity_ontology.down.sql` — the reverse migration.

- Recreate `projects` and `subprojects` tables with their original shapes (from `000_full_schema.up.sql`).
- Reverse the data mapping: activities with `parent_id IS NULL` and `kind = 'engagement'` → `projects`; activities with `parent_id IS NOT NULL` → `subprojects`.
- Restore `time_entries` columns (`project_id`, `subproject_id`, `wg_id`) and re-populate from the activity tree walk.
- Restore `expenses` columns (`project_id`, `customer_id`) — derive `customer_id` via contract link.
- Restore `working_groups.subproject_id` and `enforce_unit_tuple` (default TRUE).
- Restore `project_managers`, `project_adoptions`, `financial_cutoff_periods.project_id`.
- Drop `activities`, `activity_kinds`, `activity_adoptions`, `activity_managers`.
- **Acceptable lossiness:** the down migration is best-effort per ADR-BE-004. `billable`, `budget_amount`, `kind` metadata, and activities that don't map to the two-level model (depth > 2, or kinds other than engagement/task) are documented as lossy in a comment header.
</action>
