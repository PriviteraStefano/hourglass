<how-to-verify>
## Pre-requisites

**IMPORTANT:** Make sure Docker (SurrealDB) is running before starting. On macOS with Docker Desktop:
```bash
docker ps | grep surrealdb
```
If SurrealDB is not running:
```bash
docker-compose up -d surrealdb
```

## Step 1: Apply the seed

```bash
cd /Users/stefanoprivitera/Projects/hourglass
go run ./cmd/schema
```

**Expect:**
```
Applying schema: 001_schema.surql
Applied: 001_schema.surql
Applying schema: 003_seed_demo.surql
Applied: 003_seed_demo.surql
Schema migration completed successfully
```

If there are errors, note them for the report. The most common error would be SCHEMAFULL rejections of extra project fields (`contract_id`, `governance_model`, etc.) — this is a pre-existing schema-vs-Go mismatch documented in RESEARCH.md and does NOT block this plan (the Go server handles it on read).

## Step 2: Start the server

```bash
go run ./cmd/server
```

Server should start on :8080 without errors.

## Step 3: Verify bootstrap check

In another terminal:
```bash
curl -s http://localhost:8080/auth/bootstrap-check | python3 -m json.tool
```

**Expected:** `{"needs_bootstrap": false}` — the seed has users, so bootstrap is not needed.

## Step 4: Login as Demo Manager (primary persona, per D-14)

```bash
curl -v -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"alex.rivera@tcg.com","password":"demo123"}'
```

**Expected:** HTTP 200 with `Set-Cookie: auth_token=...` and `Set-Cookie: refresh_token=...` headers. Save the cookies.

## Step 5: Verify auth/me returns the user profile

```bash
curl -s -b auth_token=... http://localhost:8080/auth/me | python3 -m json.tool
```

**Expected:** Returns user JSON with `"email": "alex.rivera@tcg.com"`, role "manager".

## Step 6: Start frontend and verify all pages

```bash
cd web && bun run dev
```

Open http://localhost:3000 in a browser. Verify:

| Page | URL | Expected |
|------|-----|----------|
| Login | /login | Login form works — sign in as `alex.rivera@tcg.com` / `demo123` |
| Dashboard | / | Loads without errors |
| Org Hierarchy | /org-hierarchy | Shows unit tree with 8 units, units 4-8 nested under 1-3 |
| Contracts | /contracts | Lists 3 contracts: Digital Transformation Program, Cloud Infrastructure Migration, Internal Operations |
| Projects | /projects | Lists 6 projects with contract names |
| Customers | /customers | Shows "NovaTech Industries" with contact info |
| Time Entries | /time-entries | Shows sample entries for the week |
| Expenses | (check route, likely /expenses) | Shows sample expenses |

## Step 7: Login as other roles

1. **Finance user** — Log in as `mike.obrien@tcg.com` / `demo123`. Verify expense pages show data.
2. **Employee** — Log in as `emma.wilson@tcg.com` / `demo123`. Verify time entries page shows own entries.

Run `go run ./cmd/schema` a second time. Confirm it completes without errors.
