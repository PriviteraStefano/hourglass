<decisions>
## Implementation Decisions

### Register flow improvements
- **D-01:** Set `auth_token` and `refresh_token` cookies on successful registration (align with Login/Bootstrap handler behavior). Currently the Register handler returns 201 without setting cookies, forcing a separate login step.
- **D-02:** Frontend mutation already has `onSuccess` that sets query data — no change needed there, but the browser will now receive cookies from the response.

### OrgSwitcher integration
- **D-03:** Replace hardcoded `organizations={[]}` in `AppSidebar` with actual membership data from `AuthApis.membershipsQueryOpts`.
- **D-04:** Wire org switching via `AuthApis.switchOrganizationMutationOpts` in the OrgSwitcher dropdown `onClick`.
- **D-05:** On successful org switch: `client.invalidateQueries()` or `client.clear()` to refresh all data for the new org context. Also refetch `['auth', 'me']` since the profile org changes.

### Landing page / redirect
- **D-06:** After login/register, redirect to `/` which will redirect to `/time-entries`. No dashboard page in v0.1 — minimal redirect approach.
- **D-07:** Create an authenticated index route at `/` that renders a simple redirect to `/time-entries`.

### Password reset code leak
- **D-08:** Stop returning the reset code in the response body (`POST /auth/password-reset/request`). The code should be delivered out-of-band (email/SMS only in production; for development, log to server console).
- **D-09:** Increase reset code entropy from 3-digit numeric to 6+ alphanumeric characters.
- **D-10:** Rate-limit password reset verification attempts.
- **D-11:** Update frontend `requestPasswordResetMutationOpts` to handle the new response shape (no `code` field).

### Route tree generation
- **D-12:** `routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin` in Vite during `bun run dev`. No separate script needed.

### Authentication flow verification
- **D-13:** All 6 seed users must login successfully (alex.rivera, sarah.chen, mike.obrien, emma.wilson, james.park, lisa.torres / demo123)
- **D-14:** `GET /auth/me` must return full profile with role + org_id
- **D-15:** `GET /auth/memberships` must return membership list without panic
- **D-16:** Cookie refresh flow works (401 → POST /auth/refresh → retry)

### Backend fixes carried forward from Phase 0
- **D-17:** The 4 known auth bugs were fixed in Phase 0 (memberships nil pointer, auth/me empty role/org_id, units/{id}/members 500, orgs/members 500). Verify they still work — if broken, re-fix in this phase.

</decisions>

## Existing Code Insights

- `RegisterForm` — Fully built with org create/join selection, validation

### Established Patterns
- Routes use `_auth/` layout for unauthenticated pages (login, register, password-reset)
- `_authenticated.tsx` guard uses `beforeLoad` with `fetchQuery(AuthApis.profileQueryOpts)`
- Form components co-located in `-components/` dir next to route index
- Mutations use `onSuccess` callback to update query cache
- API modules export an `*Apis` object aggregating all options

### Integration Points
- `sidebar.tsx` passes `organizations={[]}` → switch to `membershipsQueryOpts`
- `OrgSwitcher` dropdown `onClick` → wire `switchOrganizationMutationOpts`
- Register success → currently no cookies → needs cookie setting in backend handler
- Password reset response → currently has `code` field → needs removal
- `/` route → needs redirect to `/time-entries`
