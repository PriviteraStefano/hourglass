**Check AUTH-01 (Login validation — error cases):**
4. `curl -v -X POST http://localhost:8080/auth/login -H 'Content-Type: application/json' -d '{"identifier":"","password":""}'` — verify 400
5. `curl -v -X POST http://localhost:8080/auth/login -H 'Content-Type: application/json' -d '{"identifier":"nonexistent@test.com","password":"wrong"}'` — verify 401

**Check AUTH-05 (Cookie refresh flow):**
6. Login as alex.rivera, capture the auth_token cookie value
7. Call `curl -v http://localhost:8080/auth/me -H 'Cookie: auth_token=INVALID_TOKEN'` — verify 401

**Check D-14, D-17 (auth/me returns role + org_id, auth bugs still fixed):**
9. Login as alex.rivera, capture auth_token, then:
10. `curl -v http://localhost:8080/auth/me -H 'Cookie: auth_token=<token>'` — verify 200 + body has "role" and "organization_id" non-empty

**Check D-15 (auth/memberships no panic):**
11. `curl -v http://localhost:8080/auth/memberships -H 'Cookie: auth_token=<token>'` — verify 200 + body has "memberships" array

**Check D-08, D-16 (password reset no code leak + refresh flow):**
12. After login, `curl -v -X POST http://localhost:8080/auth/password-reset/request -H 'Content-Type: application/json' -d '{"identifier":"alex.rivera"}'` — verify 200 + body has "message" and "expires_at" but NO "code" field
