**A. Fix Register handler cookies** (D-01) — `internal/adapters/primary/http/auth.go`:

Modify the Register handler (line 66) — after `err` check block (lines 54-64) and before `api.RespondWithJSON(w, http.StatusCreated, resp)`, insert the same 3-line cookie-setting pattern used by Login (lines 117-119):
```go
secure := cookies.IsSecureRequest(r)
cookies.SetAccessTokenCookie(w, resp.Token, secure)
cookies.SetRefreshTokenCookie(w, resp.RefreshToken, secure)
```
Change HTTP status from `http.StatusCreated` (201) to `http.StatusOK` (200) to match Login/Bootstrap convention, since the response now includes tokens (the spec changes from "resource created" to "authenticated session established").

**B. Fix password reset code entropy** (D-09) — `internal/core/services/password_reset/password_reset.go`:

Replace the `generateResetCode` function (lines 102-109). Currently uses `rand.Read` + modulo, which has bias because 256 % 62 != 0. Replace with unbiased distribution using `crypto/rand.Int` with `math/big`:
- Import `"math/big"` 
- For each of the 8 code bytes, call `rand.Int(rand.Reader, big.NewInt(int64(len(resetCodeCharset))))` and use `n.Int64()` as the index into `resetCodeCharset`.
- Keep the same charset constant, same return type, and same function signature. The `"crypto/rand"` import is already present.

**C. Verify code leak is fixed** (D-08 — read-only, no change needed):
Confirm `internal/adapters/primary/http/password_reset.go` line 44 uses `_, expiresAt, err := h.service.Request(...)` — the code IS already discarded. No action required.
