<objective>
Close **WR-02** from 14-VERIFICATION.md: the capacity workload must be period-scoped. Today the `workload` CTE sums ALL submitted+approved entries on the org's activity subtree with no `entry_date` predicate, while every sibling column (partial_abs, full_abs, declared) is bounded by `$3`/`$4` — so `available_hours = period_capacity − lifetime_workload` and historical entries drag capacity down forever (the phase goal's derived capacity query is semantically wrong).

Purpose: make the workload term obey the same period contract as the rest of the read-model, proven by a repo battery that seeds entries both inside and outside the requested period and by an HTTP boundary regression.

Output: one SQL predicate + doc-comment update + two regression batteries. The dependency on 14-09 is file-level only (both plans add tests to `availability_repository_test.go`); no semantic dependency.
</objective>
