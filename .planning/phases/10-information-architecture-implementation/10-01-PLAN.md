## Context

Phase 9 collapsed projects+subprojects into the recursive `activities` entity and deleted the `/projects*` HTTP surface. The frontend still speaks "projects": `api/projects.ts` calls dead endpoints, `types/models.ts` carries `Project`/`Subproject`, the route directory is `projects/`, and the `Role` union is missing `hr` (added to the DB CHECK in migration 012). This plan lays the foundation every other Phase 10 plan builds on.

Backend contract (from `internal/adapters/primary/http/activity_handler.go` + `internal/core/domain/activity/activity.go`):

* `GET /activities?scope=owned|adopted|all&contract_id=&parent_id=&kind=` → `ActivityResponse[]` (Activity + `parent_name`, `contract_name`, `created_by_org_name`, `adoption_count`, `is_adopted`)
* `GET /activities/{id}` → `ActivityDetailResponse { activity, ancestry[], commercial_context, billable }`
* `POST /activities` — requires `name`, `kind`, `governance_model`; optional `parent_id`, `description`, `contract_id`, `is_shared`, `billable`, `budget_amount`
* `PUT /activities/{id}` / `DELETE /activities/{id}` — finance-gated, 409 on guard sentinels
* `GET /activities/{id}/children` → children list (replaces subprojects)
* `GET /activity-kinds` → org's kind catalog (free labels, not enum)
* **No adopt endpoint** — service method exists but is intentionally not exposed.
