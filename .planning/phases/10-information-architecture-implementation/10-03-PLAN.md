# Plan 10-03 — Page shell migration (wrap-only)

<threat_model>

| Threat | Severity | Mitigation |
|--------|----------|------------|
| T-10-03-1: Wrap subtly changes layout (double padding, scroll shifts) on dense pages | medium | wrap-only rule: no re-layout, no control redesign; page inner container keeps its existing padding; e2e smoke per page is the gate |
| T-10-03-2: Error/pending states bypass the shell, leaving a chrome-less blank | medium | route `errorComponent`/`pendingComponent` render inside Body (UI-SPEC lock); Phase 8 leaf-level errorComponent convention preserved |
| T-10-03-3: Header overflow (filters + CTA exceed 48px band) | low | header overflow rule: excess moves below into page body — never a second header row |

</threat_model>

## Context

UI-SPEC amendment (2026-07-31) locks the page shell for **every** authenticated page: `<AppShell>` → `<Header>{page affordances}</Header>` → `<Body>{page content}</Body>`. The org-hierarchy page (`OrgHierarchyPage`) is the canonical reference — it already composes `Header` (OrgChartToolbar) + `Body`. `Header` is a 48px `<header>` landmark carrying the page's single `h1`; `Body` owns scrolling (`overflow-clip` + inner scroll container), is padding-free (page's inner container applies `lg` 24px padding; edge-to-edge surfaces stay 0).

Carried-over pages to wrap (no re-layout, no control redesign): time-entries, expenses, exports, contracts (index + $id), customers (index + $id), activities (index + $id — renamed in 10-01). Per-surface header content: Title (Heading 20px `text-xl font-semibold`, the page's only `h1`) + existing primary CTA/filters that fit the 48px band; whatever doesn't fit moves below into the body.
