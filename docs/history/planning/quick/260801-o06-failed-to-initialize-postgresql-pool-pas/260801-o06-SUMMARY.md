## Decisions Made

- **Migrate entrypoint `-all` → `-up` (Rule 3 blocking fix):** `cmd/migrate/main.go` only supports `-up`/`-down` (confirmed via the only commit touching it and `migrate_test.go`); `-all` had made the compose `migrate` one-shot fail with a usage error since the service was created — the demo DB had **zero tables**. `-up` is idempotent (skips "already exists").
- **recover-db SQL delivery: stdin pipe, not `-c`:** psql does **not** interpolate `:'pw'` inside `-c` (psql-specific features are rejected there — verified live). Piping SQL via stdin with a leading `\set pw <value>` line lets psql interpolate `:'pw'` safely. The plan's exact YAML produced a literal `:'pw'` syntax error, so this was corrected (Rule 1) while preserving the plan's intended `:'pw'` pattern and no-argv-leak property.
- **recover-db credentials via container env, not interpolation:** compose `$$` escapes keep `$POSTGRES_PASSWORD` in the rendered command; the container resolves it from its `environment` block at runtime. Password appears 0 times in the rendered command (T-o06-01).
- **No volume wipe:** ALTER path succeeded, so demo data was preserved (plan's preferred path).
- **Migrate re-run idempotency defect deferred** (see Deviations): pre-existing `migrations/000`/`011` non-rerunnability is out of scope; logged to `deferred-items.md`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] migrate compose entrypoint used unsupported `-all` flag**
- **Found during:** Task 1 step 3 (`docker compose run --rm migrate` verification)
- **Issue:** `cmd/migrate` only accepts `-up|-down`; the compose service passed `-all`, so the one-shot always exited 1 with a usage error. The demo DB had zero tables — the demo had never had migrations applied by this service. The plan's "`migrate -all` is idempotent" premise was false (flag never existed).
- **Fix:** Changed `entrypoint: ["/usr/local/bin/migrate", "-up", "-dir", "/migrations"]`.
- **Files modified:** deploy/demo/docker-compose.yml
- **Verification:** `run --rm migrate` exit 0, all 10 migrations applied, `seed` exit 0, app Up.
- **Committed in:** 564bc42 (Task 1 fix commit)

**2. [Rule 1 - Bug] recover-db's `-c` ALTER USER failed — psql does not interpolate `:'pw'` inside `-c`**
- **Found during:** Task 2 verification (`run --rm recover-db` per the plan's exact YAML)
- **Issue:** The plan's `command` used `psql ... -c "ALTER USER ... WITH PASSWORD :'pw';"`. psql rejects psql-specific features inside `-c` (verified live: literal `:'pw'` sent to server → `syntax error at or near ":"`). The plan's exact YAML could never work.
- **Fix:** Rewrote `recover-db` to pipe SQL via stdin with a `\set pw <value>` line before the ALTER USER, so psql's `:'pw'` interpolation applies. Credentials come from container `environment` (compose `$$` escapes) — password never in the command string (0 occurrences verified) or argv. Also fixed shell quoting of the printf format (printf emits `\"` literally, so the format uses plain `"`).
- **Files modified:** deploy/demo/docker-compose.yml
- **Verification:** `run --rm recover-db` twice → both `ALTER ROLE` (idempotent); `make demo-recover-db` exit 0; app still Up and healthy afterward.
- **Committed in:** 302c83d (Task 2 commit)

**3. [Rule 3 - Blocking, pre-existing, deferred] Migration chain not re-runnable (000_full_schema + 011)**
- **Found during:** Task 1 verification (migrate re-run after successful first run)
- **Issue:** Re-running `migrate -up` fails at `000_full_schema.up.sql` line 244: `column "subproject_id" does not exist` — migration 011 renames that column and drops the old index, so 000's `CREATE INDEX IF NOT EXISTS ... ON working_groups(subproject_id)` can never re-run. 011 itself uses unguarded RENAME/DROP/ADD statements too. **Pre-existing defect, not caused by this task's changes, and outside the plan's `files_modified` list** (fixing it means rewriting applied migration DDL — Rule 4 class, needs its own plan).
- **Action:** Deferred per scope boundary — logged to `deferred-items.md` in the plan directory. The demo is fully recovered regardless; the only unmet item is the migrate *re-run* link of Task 1's automated verify chain.
- **Committed in:** n/a (documented in deferred-items.md + this Summary)
