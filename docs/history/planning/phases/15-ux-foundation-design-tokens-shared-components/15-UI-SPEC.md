## Typography

Contract scale — **exactly 4 sizes, exactly 2 weights** (supersedes 13-UI-SPEC's 5-row scale; checker revision 2026-08-12):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro | 12px (text-xs) | 400 | 1.4 |
| Label | 14px (text-sm) | 400 | 1.4 |
| Body | 16px (text-base) | 400 | 1.5 |
| Heading | 20px (text-xl) | 600 | 1.2 |

Contract weights: **exactly 2 — 400 (regular) + 600 (semibold) only.** No other weight is used in the frozen component set. The pre-freeze `font-medium` (500) usages are remapped to 600 (explicit mapping):

| Pre-freeze usage (500) | Remap |
|------------------------|-------|
| StatusBadge base `text-xs font-medium` (`shared/status-badge.tsx:48`) | `text-xs font-semibold` — component is rewritten this phase (D-15-06) |
| EmptyState title `text-sm font-medium` (`ui/empty.tsx` EmptyTitle base class) | `text-sm font-semibold` — edit the primitive's base class during the freeze; 500 must not survive anywhere in the frozen type system |
| DataTable sort/header labels (new component) | `text-xs font-semibold` |
| Direction warning labels (D-15-04, Phase 19 render) | `text-xs font-semibold` |

Deferred (NOT in the contract scale): **Display 28px/600** — declared by 13-UI-SPEC but has no consumer this phase. A phase with a 28px consumer (e.g. Phase 26 Auth polish or a future dashboard) must re-introduce it via its own UI-SPEC revision.

Out of scope: decorative mono weights (Martian Mono 200 / Geist Mono 300) are display typefaces used by `.font-display` / `.font-text` for numeric/decorative accents — decorative fonts, NOT UI weights; not counted against the 2-weight contract.

## Color

### 60 / 30 / 10 contract (unchanged from 13-UI-SPEC)

| Role | Value | Usage |
|------|-------|-------|

| Secondary (30%) | `--card` white / `--secondary` `--base-100`, sidebar `--base-100` | Cards, sidebar, nav |
| Accent (10%) | `--primary` `--primary-400` (olive, oklch 0.765 0.177 163.223) | Primary buttons, active nav, focus ring (`--ring`), selection |
| Destructive | `--destructive` oklch(0.577 0.245 27.325) light / oklch(0.704 0.191 22.216) dark | Destructive actions only |

Accent reserved for: primary actions, active navigation state, focus/selection rings. **Never used for status semantics** — statuses render exclusively through the new role tokens below (13-UI-SPEC explicitly deferred status colors to this phase; D-15-01).

### NEW: Semantic status role tokens (UXFD-01, D-15-01/02/03) — lands in `web/src/index.css`

Exactly 5 roles. Each role = 2 tokens (`--status-{role}` + `--status-{role}-foreground`) defined in `:root` AND `.dark` as CSS variable pairs, mapped through `@theme inline` exactly like the existing `--primary`/`--destructive` pattern (→ utilities `bg-status-info`, `text-status-info`, `bg-status-info/10` etc. via `--color-status-*`). The subtle-variant tint is expressed as an alpha modifier on the strong token (`bg-(--status-info)/10`), the in-repo badge destructive recipe (`bg-destructive/10 text-destructive`) applied per role — no separate tint tokens.

| Role | `--status-{role}` light | `--status-{role}` dark | `--status-{role}-foreground` (text on solid) |
|------|------------------------|------------------------|----------------------------------------------|
| neutral | `var(--base-600)` (oklch 0.4411 0 24.82) | `var(--base-400)` (oklch 0.7084 0 23.42) | white |
| info | oklch(0.546 0.245 262.881) — blue-600 | oklch(0.707 0.165 254.624) — blue-400 | white |
| success | oklch(0.596 0.145 163.225) — emerald-600 | oklch(0.765 0.177 163.223) — emerald-400 | white |
| warning | oklch(0.769 0.188 70.08) — amber-500 | oklch(0.828 0.189 84.429) — amber-400 | **black** |
| danger | `var(--destructive)` (red-600) | `var(--destructive)` (red-400 dark) | white |

Notes (locked):
- **Danger reuses `--destructive` as its base** (D-15-01: "reused as the danger base where it fits") — `--status-danger: var(--destructive)` in both themes; the existing dark-mode swap (red-600 → red-400) carries over for free.
- **Success shares the emerald hue family with the olive accent on purpose** (the shadcn `olive` base color IS the emerald ramp — `--primary-*` values equal Tailwind's emerald ramp). Distinction is role: accent = interactive elements; status-success = informational approved/done rendering (D-15-02 meaning-first).
- Light/dark value pairs follow the existing red-600/red-400 destructive precedent (strong in light, 400-level in dark for contrast on `--base-950`).
- `@theme inline` additions (mirroring the existing block): `--color-status-neutral`, `--color-status-neutral-foreground`, `--color-status-info`, `--color-status-info-foreground`, `--color-status-success`, `--color-status-success-foreground`, `--color-status-warning`, `--color-status-warning-foreground`, `--color-status-danger`, `--color-status-danger-foreground`.
- Values verified against Tailwind v4 default palette (Context7, 2026-08-12) and `index.css` `--base-*` ramp (read 2026-08-12).
- **Direction warning tokens seeded** (D-15-04): `away` + `partial` → `--status-warning`; `over-capacity` + `invalid` → `--status-danger`. Phase 19 renders them as small inline warning labels (`text-xs font-semibold` + lucide `TriangleAlert`/`CircleAlert` icons, server message rendered verbatim per 13-UI-SPEC) — no new tokens needed, no badges.

### Status → role mapping (locked D-15-03, full vocabulary)

| Role | Statuses |
|------|----------|
| neutral | draft, open (ticket), planned (ticket), declared (absence), superseded (direction); governance badges `creator_controlled` / `unanimous` / `majority` |
| info | submitted, in_progress (ticket), active (direction), claimed (direction, derived) |
| warning | triage (ticket), pending_manager, pending_finance, lapsed (direction, derived) |
| success | approved, confirmed (absence), resolved (ticket), closed (ticket), done (direction, derived) |
| danger | rejected, dismissed (ticket), cancelled (direction), withdrawn (absence) |

## Frozen Component Set — API Contracts (UXFD-01 SC2)

All land in `web/src/components/shared/` (kebab-case filenames, named exports, `__tests__` colocation per CONVENTIONS.md), composed from existing `ui/*` primitives. Components stay presentational — server state stays in routes/hooks.

### StatusBadge (rewrite of `shared/status-badge.tsx`, D-15-06)

```
StatusBadge<S extends string>({ status, variant = "subtle", label?, mapping?, className? })
```
- Generic over the status string union so Phase 16/18/19 surfaces consume it without type churn (D-15-13).
- `mapping?: Partial<Record<S, StatusRole>>` overrides; default = exported `STATUS_ROLE_MAP: Record<string, StatusRole>` covering all five vocabularies above + `StatusRole = "neutral" | "info" | "success" | "warning" | "danger"` type export.
- Variants (color always from the status→role mapping, never hardcoded Tailwind classes):
  - `subtle` (default): `border-transparent bg-(--status-{role})/10 text-(--status-{role})`
  - `solid`: `border-transparent bg-(--status-{role}) text-(--status-{role}-foreground)`
  - `outline`: `border-(--status-{role})/40 bg-transparent text-(--status-{role})`
  - `dot`: transparent bg, `text-foreground` label + leading `size-2 rounded-full bg-(--status-{role})` dot (compact lists)
- Base: `inline-flex items-center gap-1 rounded-full border px-2 py-0.5 text-xs font-semibold whitespace-nowrap` (Micro role, 12px/600 — remapped from the pre-freeze 12px/500).
- Existing consumers (time-entries list, approval rows, etc.) keep working via the rewritten component — no API change for `EntryStatus`.

### DataTable (new, D-15-05 — on `@tanstack/react-table`, new dependency)

```
DataTable<T>({ columns, data, isLoading?, empty?, initialSorting?, pageSize = 10, onRowClick? })
```
- Headless `@tanstack/react-table` + existing `ui/table.tsx` primitives. Sorting, column definitions, client-side pagination built in (D-15-05).
- `columns: ColumnDef<T>[]`; every column header renders a sort button (lucide `ArrowUpDown` / `ArrowUp` / `ArrowDown`, Micro 12px/600 muted label). **A11y contract: each sort button carries `aria-label="Sort by {column label}"`** (e.g. "Sort by Date"); when the column is actively sorted the label switches to `"Sorted by {column label} ({direction})"` (e.g. "Sorted by Date (ascending)") and the header cell sets `aria-sort`.
- Pagination footer: "Showing {first}–{last} of {total}" + prev/next icon buttons (`ChevronLeftIcon`/`ChevronRightIcon`, 32px controls per spacing exception) + page-size select (10 / 20 / 50, default 10). **A11y contract: the icon-only pagination buttons carry `aria-label="Previous page"` / `aria-label="Next page"` respectively.**
- `isLoading` → 5 skeleton rows (`ui/skeleton`).
- `empty` → EmptyState (default copy below); `onRowClick` optional row affordance (hover row bg, `cursor-pointer`).
- Cell overflow: default `truncate` on cell content with `title` attribute; missing cell values render em-dash `—` (partial state).

### FilterBar (new, D-15-08 — details were planner discretion; pinned here)

```
FilterBar({ filters, values, onChange, onReset, searchPlaceholder? })
```
- `filters: Filter[]` where `Filter = { id: string; label: string; kind: "select" | "date-range"; options?: { value: string; label: string }[] }`.
- Layout: `flex flex-wrap items-center gap-2` — search input first (grows, `min-w-40`), then select/date-range controls, then `ml-auto` spacer, active-filter count chip, "Reset" ghost button.
- Active-filter count: derived from `values` (non-empty entries excluding the search term); chip `bg-muted text-muted-foreground rounded-full px-2 py-0.5 text-xs` ("{N} active"); Reset appears only when ≥1 filter active and clears all values.
- Stateless/presentational — values come from route search params via the consumer.

### PageHeader (new, D-15-08)

```
PageHeader({ title, description?, actions?, summary?, breadcrumb? })
```
- `title` (required, Heading typography, `truncate` on one line), `description?` (Label, `text-muted-foreground`), `actions?` right-aligned slot (`ml-auto`), `breadcrumb?` slot above the title, `summary?: { label: string; count?: number; tone?: StatusRole }[]` status summary strip (dot + label + optional count chips next to the title block, `flex flex-wrap`).
- Chips render as StatusBadge `dot` variant + count — the chosen "counts/key metric badges next to the title" option.

### EmptyState (new — thin wrapper over `ui/empty.tsx`, D-15-08)

```
EmptyState({ icon?, title, description?, action? })
```
- Default icon `Inbox` (lucide) in the existing `EmptyMedia` icon variant (muted box, `size-8`, `size-4` icon); `EmptyTitle` + `EmptyDescription` slots; `action?` ReactNode below. Wraps `Empty` root (dashed border, centered, `text-balance`).
- Typography: title = Label 14px/600 (the `ui/empty.tsx` EmptyTitle base class `text-sm font-medium` is remapped to `font-semibold` during the freeze — see Typography section); description = Micro 12px/400 `text-muted-foreground`.

### ConfirmDialog (new — consolidates the 3 per-page delete-confirm dialogs NOW, D-15-07)

```
ConfirmDialog({ open, onOpenChange, title, description?, confirmLabel, variant = "destructive",
                requiredReason?, reasonLabel?, reasonPlaceholder?, isSubmitting?, error?, onConfirm(reason?) })
```
- Built on `ui/alert-dialog` + `ui/textarea`. `variant: "destructive" | "default"` switches confirm button styling.
- **Required-reason destructive pattern carried from D-13-10/D-13-16**: when `requiredReason`, the reason Textarea shows with label, the confirm button is disabled until non-empty, and the client-side validation message is "A reason is required." — mirroring the server-side 400 invariant.
- `isSubmitting` → confirm disabled + spinner; `error?` → inline muted-danger text ("Could not complete the action. Try again." as the default message).
- Absorbs: customers delete-confirm, org-hierarchy `delete-confirm-dialog.tsx`, working-groups `delete-working-group-dialog.tsx`. The `reparent-confirm-dialog.tsx` stays as-is (not a delete pattern) — D-15-12 scope.

### Type unions (D-15-13) — `web/src/types/models.ts` + `types/index.ts` barrel

`TicketStatus = "open" | "triage" | "planned" | "in_progress" | "resolved" | "closed" | "dismissed"` · `DirectionStatus = "draft" | "active" | "superseded" | "cancelled"` (+ derived `"done" | "lapsed" | "claimed"` used by badges) · `AbsenceStatus = "declared" | "confirmed" | "rejected" | "withdrawn"` — mirroring the backend vocabularies (13-UI-SPEC API contracts; D-14-08). No UI consumes them this phase (D-15-13).
